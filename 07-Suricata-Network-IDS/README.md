# Scenario 07: Network IDS Integration & Automated Threat Mitigation (Suricata + Wazuh)

## 📌 Executive Summary
This project demonstrates an end-to-end SOC scenario integrating Suricata Network Intrusion Detection System (NIDS) with Wazuh SIEM/XDR. It covers network-based anomaly detection, automated web vulnerability scanning detection, alert fatigue mitigation through custom frequency-based correlation rules, and automated active response (SOAR) via dynamic firewall blocking (`iptables DROP`) triggered directly on the target endpoint.

## 📐 Network & Lab Architecture
SIEM / XDR Manager: Wazuh Manager 4.x (Ubuntu Server)
Target Endpoint (Victim): Ubuntu Linux + Wazuh Agent + Suricata NIDS (Ubuntu Laptop / virbr0 interface)
Attacker Host: Kali Linux (Payload Delivery & Network Reconnaissance)

## 🔍 MITRE ATT&CK Mapping
Tactic: Reconnaissance (TA0043) / Discovery (TA0007)
Technique: Active Scanning: Vulnerability Scanning (T1595.002)
Technique: Network Service Discovery (T1046)

## ⚙️ Custom Detection Rules & Active Response
1. Custom Rules Configuration (configs/local_rules.xml) Custom detection rules were engineered to correlate Suricata network alerts and web scanner signatures while mitigating Alert Fatigue:

Rule 100020 (Level 8 - HIGH): Detects automated web vulnerability scanners (Nmap, Nikto, Sqlmap) based on HTTP User-Agent headers.
Rule 100070 (Level 10 - HIGH): Correlates high-frequency hits of Rule 100020 from the same source IP within 60 seconds to detect aggressive web scanning campaigns.
Rule 100071 (Level 10 - HIGH): Correlates Suricata TCP anomaly alerts (SID 86601) generated by Nmap Stealth SYN scans from the same source IP within 60 seconds.

```xml
<group name="web,appsec,custom_web_detection,">
  <!-- Rule 100020: Web Reconnaissance / Vulnerability Scanner -->
  <rule id="100020" level="8">
    <if_group>web</if_group>
    <regex>Nikto|sqlmap|nmap|acunetix</regex>
    <description>CUSTOM DETECT: Automated Web Vulnerability Scanner Detected</description>
    <mitre>
      <id>T1595.002</id>
    </mitre>
  </rule>

  <!-- Rule 100070: Intense Web Scanning Correlation -->
  <rule id="100070" level="10" frequency="5" timeframe="60">
    <if_matched_sid>100020</if_matched_sid>
    <same_source_ip />
    <description>CUSTOM DETECT: Automatyczny skaner wyzwolony wielokrotnie z tego samego IP. Możliwy atak.</description>
    <mitre>
      <id>T1595.002</id>
    </mitre>
  </rule>
</group>

<group name="suricata,custom_network,">
  <!-- Rule 100071: Suricata Network Scan Correlation -->
  <rule id="100071" level="10" frequency="15" timeframe="60">
    <if_matched_sid>86601</if_matched_sid>
    <same_source_ip />
    <description>CUSTOM DETECT: Massive TCP anomalies detected from a single IP (Possible Nmap Stealth Scan). Suricata is correlating the traffic.</description>
    <mitre>
      <id>T1046</id>
    </mitre>
  </rule>
</group>
```

2. Active Response Configuration (configs/ossec.conf) Automatically triggers a custom SOAR script (custom-block.sh) upon detecting rules 100070 or 100071. The script immediately executes iptables -I INPUT -s <attacker_ip> -j DROP on the endpoint:
```xml
<command>
  <name>custom-block</name>
  <executable>custom-block.sh</executable>
  <timeout_allowed>no</timeout_allowed>
</command>

<active-response>
  <command>custom-block</command>
  <location>local</location>
  <rules_id>100070, 100071</rules_id>
</active-response>
```
